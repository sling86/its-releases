# Changelog

All notable changes to `its` are tracked here. Format loosely follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versioning is
[SemVer](https://semver.org/).

The `## [Unreleased]` section is hand-curated. Per-release notes are
auto-generated by `scripts/release.ts` at publish time — if a matching
`## [x.y.z]` section exists here it is used verbatim, otherwise the
script falls back to a filtered `git log` between the previous tag and
HEAD (conventional-commit prefixes only: `feat`, `fix`, `perf`,
`refactor`, `build`, `docs`, plus anything tagged `BREAKING`).

## [0.2.24] - 2026-05-19

### Changed

- **Licence switched from MIT to a proprietary licence.** Free for personal
  use and single-organisation internal use. Redistribution,
  reverse-engineering, and hosting as a service now require explicit
  permission. See [`LICENSE`](./LICENSE).
- **README rewritten** to drop the THF-Holdings-specific framing — the CLI
  is portable across any organisation. Reframed as closed-source with
  prebuilt binaries published to `sling86/its-releases`. Quick start now
  shows the binary install (one-line curl / `ItsSetup.exe`) rather than
  a source clone.
- **Source-repo links from the public-facing surface now point at
  `sling86/its-releases`** so visitors of the distribution repo don't hit
  404s on `sling86/it-cli` (which is private).

### Added

- **`scripts/release.ts` auto-mirrors `docs/`, `CHANGELOG.md`, and
  `LICENSE`** to `sling86/its-releases` on every release. Uses the
  workflow's `RELEASE_TOKEN` PAT in CI, falls back to `gh auth token`
  for local runs, skips with a console note when no token is available.
  Best-effort — sync failure does not roll back the release.

## [0.2.23] - 2026-05-19

Combined release — `v0.2.22` was tagged but its CI build failed (audit
tests bled state on Linux/Bun), so all the work originally cut as
`v0.2.22` ships here alongside the test-isolation fix.

### Added

- `--include-secrets` global flag — opts out of the default secret-redaction
  pipeline for legitimate workflows (BitLocker recovery-key handover, app
  credential recovery). Every use is audit-logged to `~/.its/audit.log` as
  a single JSON line. (`feat(output)`)
- `core/audit.ts` — append-only JSON-line audit logger. Secret-bearing flag
  values are masked before write (`--password 'TempP@ss'` → `--password ***`)
  via `sanitiseArgvForAudit()`. Directory created `0o700` and log file `0o600`
  on POSIX. Best-effort: write failures never abort the command.
- `CHANGELOG.md` — this file. Release notes now include the matching section
  (or a filtered git log) when published.

### Changed

- `README.md` — rewritten: badges row (Bun · TypeScript · providers · commands ·
  version · release · last commit · MIT), table of contents, compact
  per-provider links, three-column docs index. Dropped the 700-line inline
  command tree (still lives at `docs/index.md`). 904 → 241 lines.
- `docs/cli.md` — `--include-secrets` documented in the global-options table
  with the masking + permission details.

### Fixed

- `core/audit.ts` — `getAuditPath()` resolves `$HOME` / `$USERPROFILE` before
  falling back to `os.homedir()`. Bun on Linux caches `homedir()` at process
  start, so the test harness's `process.env.HOME = tmp` swap was being
  ignored and CI failed the two audit-log isolation tests with cross-test
  bleed. Production behaviour is unchanged when neither env var is set.

### Security

- The `--unsafe` flag (silent alias for `--include-secrets`) also trips the
  audit-log entry — bypassing redaction always leaves a trail, regardless
  of which flag name was typed.
